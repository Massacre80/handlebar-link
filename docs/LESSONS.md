# Lessons learned

Every mistake found in this project, and the rule that prevents it. Read before working; add an
entry whenever a mistake is found (what happened → rule). Rules here are binding, like AGENTS.md.

| # | Date | What went wrong | Rule |
|---|---|---|---|
| 1 | 2026-11-16 | Enabled detekt rules (`SuspendFunSwallowedCancellation`, relied on `InjectDispatcher`) that need type resolution, which `check` does not run: they never fired. | **A gate counts only after a planted violation has failed the build.** Check whether a detekt rule has `@RequiresTypeResolution` (javap on the rules jar) before relying on it. |
| 2 | 2026-11-16 | `ForbiddenMethodCall` via plain `detekt` silently did nothing; detekt 1.23's type resolution also missed `println` and flagged reachable code with Kotlin 2.4. | Same as 1. Rules that need type resolution go into `checkForbiddenCode` instead. |
| 3 | 2026-11-16 | Set detekt `constantPattern` to the Compose style, which rejected normal `CONSTANT_CASE`. | Read the default config entry (detekt-core `default-detekt-config.yml`) before overriding a rule; know which property applies to what. |
| 4 | 2026-11-16 | Split files with a regex extraction script; it silently dropped functions. | **Never restructure code with regex extraction.** Write the files out in full, then compile. |
| 5 | 2026-11-16 | Wrote an action's pinned SHA (`upload-artifact`) from memory; it was stale. | **Never write versions, SHAs or checksums from memory.** Look them up (Maven, `gh api`, release checksums) at the moment of writing. |
| 6 | 2026-11-16 | The Android docs show Hilt 2.57.1, which does not support AGP 9. | Docs examples lag. Check release notes / compatibility (AGP, Kotlin, KSP) for the exact versions used. |
| 7 | 2026-11-16 | Misread "no fallbacks" as "Android 17 only" and changed minSdk. | Restate an ambiguous constraint to the user in one line before acting on it. |
| 8 | 2026-11-16 | `:bike:link`'s public API used `:bike:protocol` types through `implementation`; it compiled only because `:app` added the module itself. | A type in a public signature comes through `api(...)`. |
| 9 | 2026-11-16 | Module boundaries were checked by regex on build files: test vs production dependencies were indistinguishable. | Check structure from the real Gradle model (configurations), not from text. |
| 10 | 2026-11-16 | A Gradle task's mapping lambda captured `Project` (configuration-cache failure); a local val shadowed a task property. | In build logic, copy `objects`/values into locals before lambdas; don't name locals like task properties. Run with the configuration cache on (default here). |
| 11 | 2026-11-16 | Reinstalled the old prototype on the phone after the user had said v2 replaces it. | The phone runs v2 only. |
| 12 | 2026-11-16 | A test suite passed on the first run but could not detect "reply subscribed after the write". | When tests pass first time, plant the bugs that matter; if one survives, the suite is missing a test (add it, e.g. an instant-reply fake). |
| 13 | 2026-11-16 | Wrote `else -> Unit` in statement `when`s (twice); ktlint wraps it into `{ Unit }`, which Kotlin 2.4 reports as an unused expression. | In a statement `when`, write an empty branch as `-> {}`, never `-> Unit`. |
| 14 | 2026-11-16 | The root Spotless target `build-logic/**/*.kt` made Gradle walk the whole tree, including other modules' `build/` while they were being written: an intermittent "Could not read path" failure. | Give file scans the narrowest root (`fileTree("build-logic")`), never a glob from the project root. |
| 15 | 2026-11-16 | Named tests with `;` and `%` in backticks: Kotlin rejects `. ; [ ] / < > : \` in names and warns on `%` (Windows). | Backtick test names use words, commas, dashes and parentheses only. |
| 16 | 2026-11-17 | Edited text that `spotlessApply` had already rewritten (wrapped lines, `-> Unit` blocks); the exact-match edits failed or did nothing. | Run `spotlessApply` first, then read the current text, then edit; an edit script must stop on the first mismatch. |
| 17 | 2026-11-17 | Typed library coordinates and versions into `gradle/libs.versions.toml` by hand (after looking them up with curl). The user forbids hand-written library entries. | **Never hand-write a library or version into the build.** Add with `./gradlew addLibrary`, update with `./gradlew versionCatalogUpdate` (user's choice, 2026-11-17; see AGENTS.md). |
| 18 | 2026-11-17 | A test reopened a DataStore file right after `scope.cancel()`; DataStore still held it ("multiple DataStores active for the same file"). | Cancellation is asynchronous: to release a resource owned by a scope, `cancelAndJoin()` its job before reusing the resource. |
| 19 | 2026-11-17 | Allowed `LogcatSink.kt` in only one of the gates for the logging rule; `checkForbiddenCode`'s println rule and detekt's `ForbiddenImport` both still failed it. | A rule enforced by two gates gets its exception in both, with the reason next to each; then plant the violation in another file to prove the exception is no wider than that one file. |
| 20 | 2026-11-17 | Named previews "font 1.5": the screenshot tool cuts file names at the first ".", so all large-text references overwrote one file (13 images instead of 24) without an error. | Count generated outputs against what was expected (tests × variants) every time. No "." in preview names. |
| 21 | 2026-11-17 | `tasks.matching { … }` in build logic created every task to test its name, including AGP's release preview task, which fails (AGP 9 runs unit tests for debug only). | Refer to tasks by exact name (`dependsOn("name")`, `mustRunAfter("name")`). Never filter tasks, not even with `tasks.named { spec }` (it also creates them; seen 2026-11-17), when lazily registered ones may fail on creation. |
| 22 | 2026-11-17 | Gave text containers the artboard's fixed height (device tiles, stat cards, the Night hero area): with large text or a short screen they clipped content or collapsed. Found by the screenshot suites. | A design height is a minimum (`heightIn(min = …)`); a page that can run out of height scrolls; check font scale 1.5 and the nine sizes before calling a screen done. |
| 23 | 2026-11-17 | Batch edit scripts stopped halfway twice after the formatter had rewrapped a file (lesson 16 again). | Lesson 16 applies to every file a batch touches: read each target's current text first; after a stop, check which edits landed before rerunning. |
| 24 | 2026-11-17 | Put the intercom card and the add-device slot side by side, each sized to its own content: their heights differed (seen by the owner in the emulator; the screenshots had it too, but I only checked for clipping). | Cards side by side share one height (`CardRow`: the row is `IntrinsicSize.Min`, each card `fillMaxHeight`). When reviewing screenshots, check alignment between neighbours, not only clipping. |
| 25 | 2026-11-17 | Lint failed again with `FileNotFoundException` under `build/spotless-clean` (first seen 2026-11-16, "cause not established"): run alone it passed. Spotless writes and deletes scratch copies there while lint, in parallel, reads files under `build/`. | A failure that passes when re-run alone is a race, not luck: find the two tasks and order them (`mustRunAfter`). Lint now always runs after the module's Spotless tasks. |
| 26 | 2026-11-17 | Recorded screenshot references on macOS while CI verifies on Linux: the bike's gradient fade and the chip's blurred shadow render differently there (up to 10 %, and 0.07 % on plain pages), so no tolerance separates noise from real change. | Record references where they are verified: Linux CI (`[record screenshots]` or the manual run), then commit the downloaded images. macOS only renders previews for looking. |
| 27 | 2026-11-17 | Inserted a function by matching the next function's `fun` line: that function's KDoc stayed above the new one (ktlint: "KDoc not allowed inside class body"). | Anchor insertions on the KDoc that starts a declaration, not on its `fun` line. |
| 28 | 2026-11-17 | Moved `checkSelfPermission` out of the function that calls `createBond`: lint no longer saw the check (MissingPermission). | Keep the permission check in the same function as the guarded call; a helper that only checks is invisible to lint. |
| 29 | 2026-11-17 | The setup bike's backlight used `Modifier.blur`, which clips to the layer's bounds by default: on the phone the glow ended in a straight edge. | A glow larger than its box needs `BlurredEdgeTreatment.Unbounded`; look at blurred effects on a device, not only in previews. |
| 30 | 2026-11-17 | First draft of setup states: a static search ring, then a bar filling over the 15 s scan; the owner wanted a loader that loops (a rounded segment sweeping fast) and failures shown in the danger colour. | A wait whose end is unknown gets an indeterminate, looping indicator, not a fill tied to a time limit; every failure state gets the danger colour and one clear action. |
| 31 | 2026-11-17 | Lime text (the step overline) and white step dots carried over from Night onto Bento's light ground, where they nearly vanish. | Check every colour choice in both looks; Night-only accents (lime text, white alphas) need a Bento counterpart. |
| 32 | 2026-11-17 | The press indication scaled what it draws, but every component put `clickable` after `clip().background()`: only the label shrank by 3 %, the pill and card never moved and nothing changed colour. The owner saw no click response on the phone. | An indication only draws what comes after it in the chain. Press feedback has two parts: a state layer in the indication (clipped by the component's shape) and `pressScale` first in the chain for the whole component, sharing one interaction source. Check presses on a device; screenshots cannot show them. |
| 33 | 2026-11-17 | Concluded "the meter does not advertise the Vehicle Information service" from service-filtered scans that returned nothing, and wrote it into the protocol notes; the first unfiltered capture showed the service advertised. The scans had probably run before the meter was advertising. The real fault was the name: "HONDA BTU 2040" plus two NUL characters (logcat drew them as four `�`, which I first took for four bytes), so a full-name match failed in our list and in Android's link popup. | A scan that finds nothing proves nothing unless the device is shown advertising at that moment. Capture first: log what an unfiltered scan sees (names, services, raw characters), then decide the filter. Clean names before matching or showing them. |
| 34 | 2026-11-17 | A Python edit script used `str.replace` without checking the match; the formatter had rewrapped two targets, so the name cleaning and the stable order never reached the app, and the owner tested a build without the fix. | Every scripted replacement asserts exactly one match and stops otherwise (lessons 16, 23). After installing a fix, confirm it runs: a log line or behaviour that only the new code produces, and the installed APK's hash. |
| 35 | 2026-11-17 | Sorted the found devices by signal on every scan result: the list reordered constantly under the rider's thumb. | Lists that update live keep a stable order (first seen); live values (signal) change in place. |
| 36 | 2026-11-17 | Ran `adb logcat -c` before each test to read a clean log: it erased the bike's first connection (series code, setup steps, the drop), and the phone's buffer kept only 3 of our lines later; the owner then asked for everything the bike sent. | Never clear the phone's log during bike tests. Capture to a file from the start (`adb logcat … >> file`, reconnecting through USB drops) and filter the file, not the buffer. |
| 37 | 2026-11-17 | The GATT probe read the HID Report Map; Android refused it (reserved for its HID host), the refusal left `BluetoothGatt` busy, and every later operation on the live link failed instantly until the next connection. | Never touch Android's reserved services (HID) from an app, even read-only. Probe an unknown device on a link that can afford to fail, and treat "every op after X failed in 2 ms" as a wedged stack, not as N separate errors. |
| 38 | 2026-11-17 | Every build the owner tested was a debug build (the release build had R8 but no signing, so it could not be installed), and the owner saw page switches stutter. The code had real costs too: the 4 MB bike render decoded on the main thread on every page open (`painterResource`), shadows re-blurred and brushes re-allocated on every frame, a full-screen blur behind the setup bike, and the glass card tracking positions with `onGloballyPositioned` on every frame of a slide. | Judge performance only on the release build (R8, profile installer; signed for local installs). Before calling a screen done, check it against the Compose performance skill: heavy decoding off the main thread and shared, `drawWithCache` for anything allocated while drawing, no blur on large areas, positions read while drawing in `Modifier.Node`s. |
| 39 | 2026-11-17 | Chained `git commit` after `./gradlew check` with `;`, so a failing check (detekt crashing on Java 25) still committed; `git add -A` also took in two files Android Studio had just written (`gradle-daemon-jvm.properties` pinning Gradle to Java 25, and parallel sync in `gradle.properties`). | Commit only as `./gradlew check && git commit`. Before every commit read `git status`: a file I did not write (IDE, tool) is checked and explained, never swept in. The daemon JVM is pinned to 21 (`updateDaemonJvm --jvm-version=21`) so Studio and the command line agree. |
| 40 | 2026-11-18 | Repeated lesson 38: installed debug builds (`installDebug`) for the owner to try the new Add device flow, and the owner found the new page transition "jittery and laggy". The first container transform also had real faults, seen only by recording the screen: Home faded out at once (the card grew over black), the page was remeasured at every in-between size (text reflowing in a tiny box), the tapped tile was stretched to full screen on the way back, and the bounds used the layout spring's slight overshoot. | Every build handed to the owner is `./gradlew :app:installRelease` (check `dumpsys package` shows no DEBUGGABLE flag). Judge motion from a screen recording (`screenrecord`, frames with ffmpeg), not from renders. Container transform: the page underneath stays until the transform settles; both contents keep their final size (`skipToLookaheadSize`) inside the shared bounds; the bounds use a critically damped spring. |
